# 234 Slides — template format & validation

Templates are contributed via **pull request to the main repo, reviewed like
code, and shipped with the app** (root CLAUDE.md §10, apps/slides/CLAUDE.md §4).
There is no separate template distribution infrastructure for v1.

## Directory structure

Each template is one directory under `/apps/slides/templates/`:

```
/apps/slides/templates/
└── <template-name>/
    ├── template.fwsl     ← the slide template in native .fwsl (JSON) format
    ├── preview.png       ← exactly 1280×720 PNG preview
    └── meta.json         ← name, author, tags[], description, license
```

## `meta.json` schema

| Field | Type | Rule |
|---|---|---|
| `name` | string | Required |
| `author` | string | Required |
| `tags` | string[] | Required, must be an array |
| `description` | string | Required, sentence case |
| `license` | string | Required, **must be `MIT` or `CC0`** |

## Validation rules (gate on every PR)

A template is valid when **all** hold:

1. `template.fwsl` parses via `parseFwsl` (a `Deck` with a `slides` array).
2. Every slide passes the auto-layout engine — `constraintCheck(slide.objects)`
   returns `true` (no overlapping objects, nothing off the 960×540 canvas).
3. `preview.png` exists and is **exactly 1280×720**.
4. `meta.json` parses and satisfies the schema above (all fields present, `tags`
   is an array, `license` ∈ {MIT, CC0}).

## Validation script

The validator lives in `src/templates/validate.ts` (pure, Node built-ins only)
and is exercised by `src/templates/templates.test.ts`, which asserts that **at
least 10 templates** ship and that **every** template validates clean.

```bash
pnpm validate:templates     # runs the validator over /apps/slides/templates
```

CI runs this on every PR (a dedicated "Validate slide templates" step in
`.github/workflows/ci.yml`; it is also covered by `pnpm test`).

## Authoring / regenerating

Templates (including their `preview.png`) are generated by
`templates/scaffold.mjs` (Node ESM, built-ins only):

```bash
node apps/slides/templates/scaffold.mjs
```

> **Preview images are generated placeholders** — a tasteful two-tone 1280×720
> fill — until an in-browser template renderer exists with the Tauri window. Each
> `template.fwsl` is a real, validated deck; the preview is regenerated by the
> scaffold script when a template's design changes. Contributors adding a
> template by hand must supply a 1280×720 `preview.png` that passes validation.
